# Contributing

Contributions should preserve the project's local-only design, bounded rendering model, data compatibility, and clean-release guarantees.

## Before submitting changes

1. Start from the public clean source, not a configured personal installation.
2. Do not commit game artwork, videos, shortcuts, personal paths, libraries, logs, status files, backups, or generated packages.
3. Keep PowerShell 5.1 and Lua 5.1 compatibility unless a deliberate compatibility change is documented.
4. Update release notes and tests when behavior or the library schema changes.
5. Run the portable release tests and the relevant native Windows checks from `TESTING.md`.
